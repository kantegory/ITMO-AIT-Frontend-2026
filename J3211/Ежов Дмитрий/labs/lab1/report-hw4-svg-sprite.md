# Домашняя работа 4: SVG-спрайт

## Цель

Вынести все используемые ранее SVG-иконки в общий SVG-спрайт. До этой ДЗ в проекте (ЛР1 + ЛР2 + ДЗ3) каждая иконка дублировалась инлайном в HTML — одни и те же контуры (логотип-молния, поиск, чек-марк, луна/солнце и т. д.) повторялись от 2 до 5 раз на разных страницах. Это раздувает HTML, делает изменения иконки болезненными (надо найти и исправить все копии) и мешает кешированию.

## Зачем нужен SVG-спрайт

Аналог CSS-спрайтов из растровой эпохи, но без потерь:
- **Одна загрузка, много вставок.** Браузер скачивает `sprite.svg` один раз, кеширует и подставляет иконку в любую страницу через `<use href="…#icon-X"/>`.
- **HTML тоньше.** Вместо 5–20 строк `<path/>` на каждую иконку остаётся одна строка-ссылка.
- **Управляется CSS.** Все иконки построены на `stroke="currentColor"` — цвет наследуется от `color` родителя, размер задаётся через `width/height` или CSS. Это идеально стыкуется с темизацией ДЗ3: при смене темы иконки автоматически перекрашиваются вместе с текстом.
- **Удобство сопровождения.** Поменять контур луны? Правим один `<symbol>` в спрайте — все 5 страниц обновляются разом.

| ID | Где используется |
| --- | --- |

| `icon-moon`, `icon-sun` | переключатель темы (везде) |
| `icon-email`, `icon-lock`, `icon-user`, `icon-shield` | поля форм входа/регистрации |

### 2. Файл спрайта (`assets/sprite.svg`)

Создан единый файл с `<symbol>`-определениями. Корневой `<svg>` помечен `style="display:none"` (никогда не рендерится сам по себе), у каждого `<symbol>` — свой `viewBox` и presentation-атрибуты (`fill="none"`, `stroke="currentColor"`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`). Это значит, что `<use>`-инстансу не нужно повторять эти атрибуты — они наследуются из символа.

Пример:

```xml
<symbol id="icon-search" viewBox="0 0 24 24" fill="none" stroke="currentColor"
        stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <circle cx="11" cy="11" r="8"/>
  <path d="m21 21-4.3-4.3"/>
</symbol>
```

### 3. Замена инлайн-SVG на ссылки

Каждый блок вида

```html
<svg width="16" height="16" viewBox="0 0 24 24" fill="none"
     stroke="currentColor" stroke-width="2" …>
  <circle cx="11" cy="11" r="8"/>
  <path d="m21 21-4.3-4.3"/>
</svg>
```

заменён на однострочный

```html
<svg class="icon" width="16" height="16" aria-hidden="true" focusable="false">
  <use href="assets/sprite.svg#icon-search"/>
</svg>
```

Сохранены только атрибуты, важные для рендера на конкретном месте (`width`/`height`, `class`, `style`, `id`, `data-icon`) — всё остальное живёт в `<symbol>`.

Чтобы не делать 50 ручных правок и не сбить отступы, написан мини-скрипт `tools/sprite_refactor.py`: он находит `<svg>...</svg>` по сигнатурам внутренних элементов (уникальные `d`/`points` атрибуты), классифицирует иконку и переписывает блок. Прогнал, проверил glob по `<path`/`<circle`/`<polyline`/`<rect`/`<polygon` — в HTML их **не осталось**.

### 4. CSS-утилита `.icon`

В `css/style.css` добавлен общий класс:

```css
.icon {
    display: inline-block;
    fill: none;
    stroke: currentColor;
    flex-shrink: 0;
}
```

`fill`/`stroke` дублируют значения из `<symbol>` ради совместимости (некоторые движки рисуют атрибуты `<symbol>` не во всех браузерах одинаково для теневого DOM `<use>`), `flex-shrink: 0` — чтобы иконки не сжимались в flex-контейнерах (раньше это писалось точечно в нескольких местах).

### 5. Совместимость с темизацией ДЗ3 и JS

- **Темизация:** иконки полностью «прозрачны» к смене темы — наследуют `currentColor`. На светлой теме они автоматически становятся тёмными, на тёмной — светлыми.
- **Переключатель темы** (`src/utils/theme.ts`) ищет внутри кнопки `<svg data-icon="sun">` / `data-icon="moon"` и переключает их `display`. Атрибут `data-icon` сохранён на новых `<svg>`-обёртках, ничего менять в JS не пришлось.
- **Show/Hide пароля** (`src/pages/login.ts`) обращается к `#eyeOn`/`#eyeOff` через ID — IDs тоже сохранены.

### 6. Проверка

```bash
npx tsc --noEmit                 # 0 ошибок
npx vite build                   # 5 HTML + sprite.svg (7.87 kB → 1.78 kB gzip)
```

Vite дополнительно прогнал `sprite.svg` через свой пайплайн ассетов — в продакшен-сборке файл переименован в `assets/sprite-<hash>.svg`, а все `<use href>` в HTML автоматически переписаны на этот же хеш. Это даёт **content-based caching**: пока спрайт не меняется, браузер тянет его из кеша вечно.

Ручная проверка:

- `npm run dev` + `npm run api`, открыл все 5 страниц — все иконки на месте, при смене темы перекрашиваются, переключатель «солнце/луна» работает, показ/скрытие пароля работает.
- Inspector в DevTools: внутри каждого `<svg>` лежит `<use>` со ссылкой на нужный `#icon-…`.
- В Network видно только **один** GET к `sprite.svg` на загрузку страницы — далее всё из кеша.
- Lighthouse: оценки не изменились, размер HTML слегка уменьшился (например, `dashboard.html` стал ~13.9 kB вместо ~16 kB до).
