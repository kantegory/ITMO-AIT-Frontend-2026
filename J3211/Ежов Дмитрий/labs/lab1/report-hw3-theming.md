# Домашняя работа 3: CSS-переменные, темизация сайта

## Цель

Реализовать темизацию ранее сделанного сайта (ЛР1 + ЛР2): добавить вторую тему поверх существующей. По заданию допускалось либо «светлая ↔ тёмная с ориентиром на системные настройки», либо «две кастомные темы с переключателем через JS». Я объединил оба подхода — есть и переключатель в UI, и автоматический выбор по `prefers-color-scheme` для первого визита.

## Подход

В исходном проекте (ЛР1) уже была сделана базовая работа: все цвета, фон, бордеры и тени были вынесены в `:root` как CSS-переменные (`--bg-*`, `--text-*`, `--border-*`, `--gradient-primary`, …) и далее использовались через `var(...)` в `css/style.css` и инлайн-стилях каждой HTML-страницы. Это сделало переключение темы дешёвым — достаточно подменить значения переменных, не трогая разметку.

Алгоритм выбора темы при загрузке страницы:

1. Если в `localStorage['app-theme']` лежит `light` или `dark` — используем сохранённое значение.
2. Иначе спрашиваем у системы через `window.matchMedia('(prefers-color-scheme: light)')`.
3. Тема применяется как атрибут `data-theme="light|dark"` на `<html>`.

Переключение темы пользователем перезаписывает `localStorage` и убирает «следование за системой» — это поведение, которое все привыкли видеть в современных приложениях (Twitter, Linear, GitHub).

## Что было добавлено

### 1. Новые CSS-переменные (`css/style.css`)

К существующему набору добавлены семантические переменные для того, что раньше было захардкожено внутри селекторов:

```css
--card-bg:      rgba(26, 26, 46, 0.8);   /* фон карточек .card-glass */
--card-shadow:  0 4px 6px rgba(0,0,0,0.4), ...;  /* тень карточек */
--grid-line:    rgba(139, 92, 246, 0.04); /* линии .bg-grid */
--row-hover:    rgba(139, 92, 246, 0.05); /* hover-фон строк */
--nav-hover:    rgba(139, 92, 246, 0.08);
--nav-active:   rgba(139, 92, 246, 0.14);
--color-scheme: dark;                     /* для CSS-свойства color-scheme */
```

Базовый блок переменных теперь привязан к двум селекторам:

```css
:root, [data-theme="dark"] { ... }  /* тёмная тема (по умолчанию) */
[data-theme="light"]       { ... }  /* светлая тема */
```

И поправлено три места, где жёстко стояли «тёмные» rgba:

- `.card-glass { background: rgba(26, 26, 46, 0.8); box-shadow: 0 4px 6px ...; }` → `var(--card-bg)`, `var(--card-shadow)`.
- `.bg-grid { background-image: linear-gradient(rgba(139, 92, 246, 0.04) ...); }` → `var(--grid-line)`.

После этого ни одна страница не содержит цветовых литералов вне `:root`-блоков — вся палитра управляется через переменные.

### 2. Светлая тема

Переопределение переменных под светлый дизайн с сохранением фирменной фиолетовой акцентной палитры:

```css
[data-theme="light"] {
    --bg-base:     #f6f4ff;            /* мягкий лавандовый */
    --bg-surface:  #ffffff;
    --bg-elevated: #ffffff;
    --bg-overlay:  #f1edff;

    --violet-500: #7c3aed;             /* акцент сдвинут темнее ради контраста */
    --violet-400: #6d28d9;
    --violet-300: #5b21b6;

    --text-primary:   #0f172a;
    --text-secondary: #475569;
    --text-muted:     #64748b;
    --text-accent:    #6d28d9;

    --border-subtle: rgba(124, 58, 237, 0.18);
    --border-accent: rgba(124, 58, 237, 0.55);

    --glow-violet:  0 0 20px rgba(124, 58, 237, 0.18);
    --card-bg:      rgba(255, 255, 255, 0.82);
    --card-shadow:  0 4px 14px rgba(76, 29, 149, 0.08), ... ;
    --grid-line:    rgba(124, 58, 237, 0.06);
    --color-scheme: light;
}
```

Дополнительно затемнены семантические цвета `.status-badge.*`, `.priority.*`, `.stat-value.*` для светлого фона — иначе бледно-жёлтый `#fbbf24` и салатовый `#34d399` теряли читаемость на белом. Декоративные блобы `.bg-glow-1/2` тоже приглушены в светлой теме.

На `<html>` повешен `color-scheme: var(--color-scheme)` — браузер автоматически перекрашивает нативные виджеты (скроллбары, селекты, autofill) под выбранную тему.

### 3. Плавный переход

При смене темы интерактивные поверхности плавно перекрашиваются:

```css
html, body, .card-glass, .form-input, .icon-btn, .nav-item,
.stat-card, .task-table, .topbar, .sidebar, .lab-nav-strip {
    transition: background-color var(--transition), color var(--transition),
                border-color var(--transition), box-shadow var(--transition);
}
```

### 4. JS-переключатель темы (`src/utils/theme.ts`)

Маленький TypeScript-модуль (~50 строк), который:

- читает/пишет `localStorage['app-theme']`,
- слушает `matchMedia('(prefers-color-scheme: light)')` и реагирует на смену системной темы, **но только если пользователь сам ещё не выбирал** (т.е. не перетирает явный выбор),
- делегированно перехватывает клики по любому элементу с атрибутом `data-theme-toggle` и переключает тему,
- синхронизирует иконку и `aria-pressed/aria-label` всех таких кнопок на странице.

Подключается первой строкой каждой страницы:

```ts
import { initTheme } from '../utils/theme';
initTheme();
```

### 5. Кнопка переключения в разметке

Кнопка-переключатель с двумя SVG (луна/солнце) добавлена:

- В топбаре `dashboard.html`, `search.html`, `task.html` — слева от остальных иконок-кнопок.
- На страницах входа и регистрации (`index.html`, `register.html`) — плавающей в правом верхнем углу через класс `.theme-toggle-floating`, потому что у них нет топбара.

Кнопка использует `data-theme-toggle` как маркер и доступна с клавиатуры (это `<button type="button">` с `aria-pressed`, который автоматически обновляется в `theme.ts`).

### 6. Защита от мигания (FOUC)

Vite-импорты у нас в `<script type="module">`, который выполняется **после** парсинга и первичного рендера. Если оставить применение темы только в `theme.ts`, при перезагрузке страница на доли секунды рисуется в тёмной (значение по умолчанию из `:root`) — и только потом перекрашивается в светлую. Это мигание особенно неприятно у пользователей со светлой системной темой.

Решение — мини-скрипт в `<head>` каждой страницы, **до** загрузки стилей и модулей:

```html
<script>
  (function () {
    var t = localStorage.getItem('app-theme');
    if (t !== 'light' && t !== 'dark') {
      t = window.matchMedia('(prefers-color-scheme: light)').matches ? 'light' : 'dark';
    }
    document.documentElement.setAttribute('data-theme', t);
  })();
</script>
```

Скрипт инлайновый и синхронный (без `defer`/`async`) — он успевает выставить `data-theme` до того, как браузер применит CSS, и стили сразу подбирают нужную ветку. После загрузки `theme.ts` подхватывает дальнейшую интерактивность.

## Проверка

### TypeScript + Vite build

```bash
npx tsc --noEmit     # 0 ошибок
npx vite build       # 5 HTML + единый theme-*.css (12.83 kB → 3.34 kB gzip)
```

Светлая и тёмная темы лежат в одном CSS-файле — это нормально, обе ветки переменных вместе занимают порядка 1 кБ gzip.

### Ручная проверка

- `npm run dev` + `npm run api`, открыл все 5 страниц поочерёдно.
- Системная тёмная: при первом заходе сайт открывается в тёмной — ОК.
- Переключил системную тему ОС в светлую (с открытой вкладкой) — сайт мгновенно перекрасился (сработал MQ-listener), без перезагрузки.
- Кликнул по кнопке-переключателю — тема инвертировалась, в `localStorage` появилась запись `app-theme=light`.
- Перезагрузил страницу — выбор сохранился; мигания при загрузке нет благодаря inline-скрипту.
- Дальше менял системную тему — сайт **не реагирует**, так как пользователь сделал явный выбор (это правильно).
- Очистил `localStorage['app-theme']` → сайт снова начал слушать систему.
- Прошёлся по всем страницам с Tab — кнопка темы получает фокус-ринг, активируется по Enter/Space, `aria-pressed` обновляется (проверял через Firefox Accessibility Inspector).
- Прогнал Lighthouse Accessibility на `index.html` и `dashboard.html` в светлой теме — оценки не упали относительно ЛР2 (100 / 98), контрастность текста на белом — в порядке.

## Итог

- Сайт корректно поддерживает обе темы, никакая разметка под темизацию не дублировалась — всё через CSS-переменные и один атрибут на `<html>`.
- Сохранена системная-первая логика (`prefers-color-scheme`), но с возможностью переопределить выбор пользователем.
- Нет вспышки неправильной темы при загрузке (FOUC) — inline-скрипт в `<head>` выставляет `data-theme` до применения CSS.
- Переключатель доступен с клавиатуры и корректно озвучивается скринридером (`aria-pressed` + говорящий `aria-label`).
- Логика темы изолирована в одном модуле `src/utils/theme.ts` (~50 строк TS), импортируется одной строкой из каждой страницы.
